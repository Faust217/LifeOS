# LifeOS V0.1 Scope

**Milestone:** V0.1 Finance Core

**Status:** Scope baseline; implementation not started

**Baseline date:** 2026-08-17

**Source:** Master Project Blueprint v0.2

## Goal

V0.1 is the first usable replacement path for the owner's current Bluecoins workflow. It establishes the repository and runtime foundation, implements reliable personal finance semantics, imports and reconciles real history, exports data, and proves backup/restore.

The milestone is successful only when it works with real data and without AI. It is not a fake-data demo and does not include later LifeOS domains.

## Required Finance Semantics

- `FinancialEvent`, `AccountMovement`, and `CategoryAllocation` form the lightweight ledger baseline.
- Money uses integer minor units plus currency.
- Transfers and credit-card payments move value but do not become new spending.
- Account balances and reports are deterministic application/database results, not AI calculations.
- Financial corrections preserve audit metadata; archived accounts and voided events preserve history.
- Cross-currency totals never silently combine currencies.
- All data is owner-scoped.

See [DOMAIN_MODEL.md](DOMAIN_MODEL.md) for the exact conceptual meanings.

## Import Acceptance Boundary

The owner has real Bluecoins history. V0.1 must:

1. parse an anonymized representative export through a source adapter;
2. normalize records into canonical application inputs;
3. validate data and show a dry-run preview;
4. require explicit mapping for unresolved accounts and categories;
5. commit through a traceable `ImportBatch` with source identity or row fingerprints;
6. report failures without direct table insertion or manual SQL repair;
7. reconcile account and category totals against the source data.

## Explicitly Out of Scope

- AI chat or provider integration; only architectural boundaries and contracts are reserved.
- Plans, travel, Wishlist, Assets, People, and Split features.
- Bank synchronization, receipt OCR, and push notifications.
- SaaS billing, organizations, and collaboration.
- A native Flutter client.
- Automatic FX feeds or investment portfolio tracking.
- A drag-and-drop or resizable dashboard editor; V0.1 only preserves dashboard composability in the architecture.
- Health/wellness data, meal tracking, and health reminders.
- Microservices, Redis, a vector database, a background-job platform, or object storage without a demonstrated V0.1 need.
- MCP integration beyond preserving its future adapter boundary.

## Exit Criteria

V0.1 is complete only when all of the following are true:

- Real Bluecoins history can be dry-run, imported, and reconciled for account and category totals.
- Income, expense, transfer, and credit-card behavior produces correct balances and reports.
- A clean Docker environment starts through one documented process.
- A prior schema version upgrades through migrations without resetting data.
- Structured exports complete successfully.
- A PostgreSQL backup has been restored successfully.
- Core tests pass.
- The owner uses LifeOS with real data for a meaningful trial period without a blocking issue.

## Definition of Done for V0.1 Work

- Business rules live in domain/application services, not only in the web client.
- Every schema change includes a new migration and upgrade test.
- API contracts and tests are updated together.
- Error paths and owner isolation are tested.
- Manual non-AI workflows are complete.
- User-visible behavior receives minimal documentation or release notes.
- Work stays inside this scope unless the Product Owner explicitly changes it.
