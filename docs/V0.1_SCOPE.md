# LifeOS V0.1 Scope

**Milestone:** Invite-only online Alpha

**Status:** Product direction approved in Issue #16; ADR-013, ADR-014, ADR-016, ADR-017, ADR-018, ADR-019, ADR-020 and ADR-021 accepted; Issues #18–#36 delivered; Issue #38 complete, manually verified by the Product Owner and approved for final delivery

**Date:** 2026-11-02

**Sources:** Master Project Blueprint v0.2 (historical); Product Owner-approved [Issue #16](https://github.com/Faust217/LifeOS/issues/16) (current scope)

## Goal

V0.1 gives the Product Owner and a small number of invited testers useful mobile-first Today, Money, Plans, and Me workflows. Google sign-in verifies identity, but only an invitation grants access. Each person's data remains private. The Alpha is online; offline transaction capture is V0.2 work.

The former single-user, Bluecoins-first V0.1 scope is intentionally replaced by Issue #16. The historical blueprint and ADRs remain preserved. Bluecoins import moves to V0.3 or later; first-class import/export and safe-import principles remain requirements.

## In Scope

| Area | V0.1 capability |
| --- | --- |
| Identity | Google sign-in, invitation-gated access, protected sessions, sign-out, and independent user data |
| Today | Basic life overview from the user's own Money and Goal data |
| Money | Manual income and expense entry, accounts, categories, transaction history, deterministic balances, and correct transfers |
| Plans | Simple checklist-based Goals; no budget or trip workflow |
| Me | Profile, sign-out, and basic data management, including export access |
| Portability | Suitable structured export of the user's implemented data and useful finance CSV export |
| Operations | Tested backup/restore, migration upgrade checks, privacy-safe logs, and cost-aware private Alpha testing |

The mobile-first React Web/PWA uses the shared REST/OpenAPI contract and Go application services. Foundation #1–#15 remains the technical base. Core behavior works without AI.

## Required Finance Semantics

- `FinancialEvent`, `AccountMovement`, and `CategoryAllocation` form the lightweight ledger baseline.
- Money uses integer minor units plus currency.
- Transfers and credit-card payments move value but do not become new spending.
- Account balances and reports are deterministic application/database results, not AI calculations.
- Financial corrections preserve audit metadata; archived accounts and voided events preserve history.
- Under accepted ADR-016, Delete hides an owned posted or voided event from normal views. Posted Delete removes its financial effects atomically; already-voided Delete does not reverse them again. Linked ledger rows remain internally, and Delete does not fabricate Void metadata. Backups can retain or reintroduce earlier versions.
- Cross-currency totals never silently combine currencies.
- All data is owner-scoped.
- The authenticated, invited user's identity determines owner scope; a client-supplied owner ID is not authorization. Test reads, writes, summaries, and exports for cross-user denial.
- Advanced credit-card behavior may be deferred, but transfers must not be implemented with incorrect spending or account effects.
- Issues #33/#34 delivered opening-balance effective-instant correctness and owner-scoped idempotent financial writes under Accepted ADR-018/019. Real personal-finance use still requires the separately accepted Personal Data Ready gate, including verified restore, non-destructive upgrade and secure persistent operation.

Issue #36 implements historical post-transaction account balances, Option B and continuous History under its approved design; final regressions and Product Owner manual 390px review passed, with delivery authorized on 2026-11-04. 320px, physical mobile and native browser automation remain unverified. API-backed search/filtering stays planned for V0.2. These later capabilities were not Issue #24 acceptance gates.

See [DOMAIN_MODEL.md](DOMAIN_MODEL.md) for the exact conceptual meanings.

## Import Timing

Bluecoins import is V0.3 or later. Its accepted dry-run, mapping, traceable-batch, idempotency, reconciliation, and controlled rollback requirements remain in ADR-009; they are not V0.1 acceptance gates.

## Explicitly Out of Scope

- AI runtime and MCP integration; only architectural boundaries remain.
- Offline writes/synchronization and Wishlist (V0.2).
- Bluecoins import, further Plans features, and Trips (V0.3 or later).
- Assets, People, and Split features.
- Bank synchronization, receipt OCR, and push notifications.
- Public signup, SaaS billing, organizations, and collaboration.
- Native mobile applications; Capacitor is only a future candidate.
- A full Admin Dashboard; later metrics must avoid unnecessary private financial detail.
- Advanced credit-card behavior unless needed for transfer correctness.
- Automatic FX feeds or investment portfolio tracking.
- A drag-and-drop or resizable dashboard editor; V0.1 only preserves dashboard composability in the architecture.
- Health/wellness data, meal tracking, and health reminders.
- Microservices, Redis, a vector database, a background-job platform, or object storage without a demonstrated V0.1 need.

## Exit Criteria

V0.1 is complete only when all of the following are true:

- An invited Google account can sign in and sign out; an uninvited account cannot enter. Sessions expire or revoke safely.
- The Product Owner and an invited tester can use Today, Money, Plans, and Me on a mobile viewport without seeing or changing each other's data.
- Manual income, expense, and transfer workflows produce correct balances and transaction history. Transfers do not become new spending.
- Goal checklists can be created and progressed without affecting account balances.
- Each user can export the implemented personal data in a suitable structured format and finance CSV; exports contain only that user's data.
- Security tests cover invitation enforcement, session and owner boundaries, cross-user record IDs, and export isolation.
- New schema changes have numbered migrations and clean/upgrade-path checks. OpenAPI, generated types, and contract tests match implemented endpoints.
- A PostgreSQL backup is restored and restored application data verified before the Alpha relies on personal records.
- Private online testing has reviewed TLS, secrets, database transport, operational endpoint exposure, and spending controls. Approximately USD $10 is a testing target, not a production guarantee.
- The Product Owner and testers complete a meaningful trial without a blocking issue.

## Definition of Done for V0.1 Work

- Business rules live in domain/application services, not only in the web client.
- Every schema change includes a new migration and upgrade test.
- API contracts and tests are updated together.
- Error paths and owner isolation are tested.
- Manual non-AI workflows are complete.
- User-visible behavior receives minimal documentation or release notes.
- Every implementation issue includes the Function-level Data Flow required by AGENTS.md, with actual file and function names before closure.
- Work stays inside this scope unless the Product Owner explicitly changes it.

### Safe Goal Delete (#38)

Active/completed/archived Goals can be confirmed-deleted from normal views while retaining internal checklist relationships. Same-owner repeated Delete is a guarded 204 no-op; deleted-parent reads/mutations are 404. Accepted ADR-021 explicitly permits the newly introduced deleted-Goal state to be omitted from normal JSON v1/v2 without changing schemas/goldens; Finance CSV and other versioning rules remain unchanged. Normal export is not a database backup. Old Planning readers/writers and exports must drain before future v12 activation. The Product Owner manually verified successful deletion and approved delivery. Full rendered 320px/390px, keyboard/focus and physical-mobile checks remain incomplete; the Personal Data Ready restore gate remains separate.
